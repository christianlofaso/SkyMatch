# Caching

All caching in `cache.py` against **Postgres** (Supabase in prod; local via `backend/docker-compose.yml`). The connection pool lives in `db.py`; the schema is created by **Alembic** (`alembic upgrade head`, migration `0001_initial_schema`), NOT by `init_db()`, which now only warms the pool. `cache.py` keeps the same public function names/signatures as the old SQLite layer; async routes call them through `asyncio.to_thread`.

| `people_search_cache` | `filter_hash` | 7 days | List of LinkedIn people results |

Keyed on the listing's `content_hash` (a re-parse → new hash → fresh reasoning), else its url; location is already folded into `profile_hash`. |
| `cost_events` | `id` (`BIGINT … IDENTITY`); queried by `created_at` window | append-only | Spend + savings ledger written by `lib/cost.py`. `kind='call'` rows carry real `input/output/cache_read/cache_write` tokens + actual `usd`; `kind='hit'` rows carry `est_saved_usd` for a full-call cache avoidance (`usd=0`). Tagged with `session` (the `cost_session` name), `label`, `model`. Read by `GET /cost/summary`, and summed by `sum_spend_since(since)` (rolling `usd` of `kind='call'` rows) for the spend-cap kill switch in `lib/guard.py`. |

Holds the **pre-annotation, pre-parse** listing (no per-user `fit_explanation`). |
| `metro_rotation` | `metro` | None | `{added_at, source}`, which metros have a pre-ingested `local` pool. Rotation size doesn't affect serving cost (one metro read per request) but does scale the worker's per-run local-ingest time. |

**`listing_store` is the only multi-row collection table** (everything else is one blob per key). It is NOT TTL-on-read like the caches: `get_listings(niche_key, bucket, *, only_valid=True, max_age=None)` filters on `status='valid'` and optionally `last_validated >= now-max_age`; rows are pruned by `prune_stale_listings(max_age)` (deletes by `last_seen`). The composite PK lets the same URL coexist across niches/buckets (a Stripe listing is `big_tech` for every national field AND in `_reach`). `niche_key` is `"_national"` (startup/big_tech), `"_reach"` (reach), or a parsed metro (local). Writers: `upsert_listing` (`INSERT ... ON CONFLICT(niche_key,bucket,url) DO UPDATE`, preserves `first_seen`), `mark_listing_dead`, `prune_stale_listings`, `count_listings_by_niche_bucket`.

**Precompute columns + parse pass.** `parsed_json` (Haiku-extracted `{title, company, company_description, location, skills[], seniority, role_category, is_internship, requires_phd, sponsorship}`) and `embedding` (normalized float32 Voyage vector, raw bytes) are filled **once per listing** by `worker/ingest.py`'s `parse_pass()`, NOT in the request path. `parsed_at IS NULL` is the single "needs work" sentinel: `get_listings_to_parse()` returns those rows; `set_listing_parse()` stamps them (parse success alone sets `parsed_at`; the embedding is best-effort and stays NULL if Voyage is down). `upsert_listing`'s `ON CONFLICT` **NULLs `parsed_at` when `search_title`/`snippet`/`verified_location`/`company` change** (using `IS DISTINCT FROM`, not `<>`, so NULLs compare correctly), so a content change triggers re-parse next run. On Postgres these precompute columns are part of `listing_store`'s `CREATE TABLE` in the Alembic `0001` migration (no `ALTER` needed). `idx_listing_unparsed (status, parsed_at)` keeps the parse-pass scan cheap. **Caveat:** changing `EMBED_MODEL` orphans stored vectors (serving only cosine-matches the same model+dim and treats the rest as unranked); `content_hash` does NOT fire on a model swap, reset manually with `UPDATE listing_store SET parsed_at=NULL`.

**Concurrency.** `db.py` hands out pooled `psycopg` v3 connections (`get_db()` → `pool.connection()`, commit-on-exit / rollback-on-exception); Postgres MVCC lets the standalone worker process and uvicorn read/write concurrently with no WAL/sidecar files. Prod connects through the Supabase pgBouncer **pooler** (transaction mode), so the pool sets **`prepare_threshold=None`** (server-side prepared statements break under transaction pooling), keep that. Pool size is `DB_POOL_MIN`/`DB_POOL_MAX` (budget Supabase's backend cap across 2 web replicas + the worker).

**Current key format** is derived from `_compute_job_id(url, text)` → `"url:<canonical_url>"` when a URL is provided, `"text:<sha256(normalize)[:32]>"` otherwise. Same URL across fetches → same key (fixes Firecrawl-induced cache misses). `profile_hash` hashes the full canonical `profile.model_dump_json()` (fixes an earlier 500-char truncation bug from the legacy `analysis_cache` table). That legacy table can be dropped in a future cleanup.

**Most tables use a single `data TEXT NOT NULL` column.** Exceptions: `user_analysis_cache` adds a `mode TEXT NOT NULL` column for selective deletes; `listing_store` and `metro_rotation` are typed multi-column tables (not the `data`-blob shape) with their own helpers; `cost_events` is an append-only typed ledger (`insert_cost_event` / `query_cost_events` / `sum_spend_since`); `app_flags` is a typed `key/value/updated_at` store (`get_flag` / `set_flag`). The generic `_get`/`_set` helpers work for the blob caches (incl. `annotate_cache`); `set_user_analysis_cache`, the `listing_store` helpers, the `metro_rotation` helpers, `insert_cost_event`, and `set_flag` write directly.

**Cost + savings ledger (`cost_events`).** `lib/cost.py`'s `record_usage` now persists every Claude call as a `kind='call'` row (alongside its existing `[cost]` stdout log), and `record_cache_hit(label, model)` writes a `kind='hit'` row whose `est_saved_usd` is the call's representative cost (per-label `_HIT_ESTIMATE` table), recorded at the two high-value cache-hit sites: the annotate cache (`internships.py`) and the `/analyze/batch` quick-verdict cache (`analyze.py`). Rows are tagged with the active `cost_session` name via a `_session_name` ContextVar. `GET /cost/summary?days=N` (`routes/cost.py`) aggregates the window: `total_spend_usd`, `total_saved_usd`, per-model / per-session spend, hits-by-label, and prompt-cache token efficiency. All USD is approximate (price table + hit estimates in `lib/cost.py`); full-mode `/analyze` cache hits are **not** counted (multi-probe → would double-count).

**Two spend SUMs over `cost_events`, split by `cost_session` tag (M5).** `sum_spend_since(since)` powers the user-facing spend-cap kill switch (`lib/guard.py`) and counts **user-facing** spend only; it **excludes** rows whose `session LIKE 'worker:%'` (a NULL session counts as request-path). `sum_worker_spend_since(since)` is the inverse; it sums only `worker:%`-tagged rows and powers the ingestion worker's own soft cap (`WORKER_SPEND_CAP_USD_DAILY`, enforced in `worker/ingest.py:parse_pass`). The tag comes for free from the `cost_session` the call ran under: the worker opens `cost_session("worker:ingest")` around its parse pass, while request paths use `/run`, `/analyze …`, etc. `query_cost_events` (and thus `/cost/summary`) is **unfiltered**, so worker spend stays visible there.

**To clear a table** (e.g. after changing validation logic), run SQL against the DB, e.g. with `psql "$DATABASE_URL"`:
```
psql "$DATABASE_URL" -c "DELETE FROM url_validation_cache;"
```

**To fully reset:** `alembic downgrade base && alembic upgrade head` (drops + recreates all tables + re-seeds `metro_rotation`). Locally you can instead `docker compose down -v` to wipe the data volume, then `docker compose up -d db && alembic upgrade head`.
